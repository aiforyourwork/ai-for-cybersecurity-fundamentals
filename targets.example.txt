# Sample targets file for tutorial-02.
#
# Format:
#   URL                       (GET — sqlmap tests query-string params)
#   URL | DATA                (POST — DATA is application/x-www-form-urlencoded)
#
# Blank lines and '#' comments are ignored. The cookie is NOT per-line —
# pass it once via --cookie on the CLI.
#
# Copy this file to targets.txt, edit it, then run:
#
#   python -m tutorial_02 \
#       --targets-file targets.txt \
#       --cookie "JSESSIONID=<paste-current-value>"
#
# IMPORTANT — POST data structure must be known up front. sqlmap can't
# discover form fields on its own for a bare POST endpoint: without
# --data it tests only query-string params (and a POST endpoint typically
# has none), so the run reports "no parameter(s) found for testing" and
# moves on. Capture the wire format once via DevTools Network → Copy
# as cURL, then paste the form body after the `|` for each line.


# Lesson 9 — Compromising integrity (string SQLi).
# Lesson is genuinely vulnerable, but sqlmap usually can't confirm at default
# --level/--risk: WebGoat's uniform JSON response envelope foils the
# response-diff heuristic. Included on purpose as a "tested, not confirmed"
# example — the AI analyst should faithfully relay that.
http://localhost:8080/WebGoat/SqlInjection/assignment5a | account=Smith&operator=or&injection=1+%3D+1


# Lesson 10 — Numeric SQLi (the headline find).
# Black-box: sqlmap discovers userid is injectable, login_count is parameterised.
# The asymmetric finding is what the AI analyst makes immediately visible.
http://localhost:8080/WebGoat/SqlInjection/assignment5b | login_count=1&userid=1


# Lesson 11 — Compromising confidentiality with String SQL injection.
# Lesson story: "John Smith" with TAN 3SL99A wants to dump ALL employees'
# salaries from the `employees` table. Backend query:
#   SELECT * FROM employees WHERE last_name = '<name>' AND auth_tan = '<auth_tan>'
# Two string-context parameters — exercises sqlmap on quote-escape payloads
# (different shape from Lesson 10's numeric injection).
# Wire values captured from a browser submit — sqlmap doesn't care about
# the specifics, only that the baseline isn't a 400.
http://localhost:8080/WebGoat/SqlInjection/attack8 | name=a&auth_tan=1


# Lesson 12 — Compromising integrity via query chaining.
# Lesson story: append a second statement with `;` to UPDATE the attacker's own
# salary. Same form fields as Lesson 11 (name + auth_tan). Tests sqlmap's
# stacked-queries technique specifically — HSQLDB allows multi-statement
# execution, so this is one of the rare cases where stacked queries actually
# land.
http://localhost:8080/WebGoat/SqlInjection/attack9 | name=a&auth_tan=1


# Lesson 13 — Compromising availability (DROP TABLE).
# Lesson story: delete the `access_log` table entirely so prior queries
# leave no trace. Single form field — note the wire name is `action_string`,
# NOT `action` as the UI label might suggest. Caught via DevTools cURL
# capture; a textbook example of why the capture procedure matters. Lesson
# is destructive by design; WebGoat resets per session, so safe to retry.
http://localhost:8080/WebGoat/SqlInjection/attack10 | action_string=a


# Negative control: a JSON-API endpoint with zero parameters.
# sqlmap reports "no parameter(s) found for testing in the provided data" —
# a perfectly clean negative finding. Including it proves the analyst doesn't
# hallucinate vulnerabilities on parameter-less targets. (For a more rigorous
# negative control — an endpoint that has parameters AND is properly
# parameterised — try /WebGoat/login or a /WebGoat/labels.mvc target with
# its expected fields; sqlmap will then fully test and report "not injectable".)
http://localhost:8080/WebGoat/service/lessonmenu.mvc
